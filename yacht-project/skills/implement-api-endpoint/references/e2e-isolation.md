# E2E-изоляция Booking ↔ Catalog (справочник)

Подгружай этот файл только когда нужна сквозная проверка двух сервисов **без** правок рабочего репозитория.

## Ограничения

- Не изменяй исходники, тесты, конфиг, зависимости и git рабочего проекта. Не чини баги автоматически.
- Временные артефакты — только во внешнем temp-каталоге. Не подключайся к рабочим БД.
- Отдельные PostgreSQL Booking и Catalog (предпочтительно tmpfs, уникальные имена, без постоянных томов). EF InMemory для этой проверки недостаточен.
- Отдельная сеть контейнеров; порты клиенту на loopback. Без реальных паспортов/платежей/секретов.
- Если изоляцию нельзя подтвердить — не пиши в БД; опиши препятствие.

## Контекст (`yacht-project/`)

- BookingService, CatalogService (`Protos/catalog.proto`), MockGims.
- `BookingServiceE2eFactory` — InMemory/stubs: дополнение, не доказательство сквозного Booking↔Catalog.
- Временные C#-провеки вне репо: xUnit + FluentAssertions; не добавляй проект в solution.

## Порядок

1. Прочитай контроллеры/DTO/Application/domain/middleware/gRPC/Catalog и README. Матрица «вход → ответ → состояние сервисов».
2. Зафиксируй `git status`. Temp dir + копия исходников без `.git`/секретов.
3. Явно задай connection strings и `IntegrationServices__CatalogGrpcUrl` / `GimsBaseUrl` на стенд.
4. Не поднимай штатный `docker-compose.yml` без изоляции. Catalog: HTTP/1 `:8080`, gRPC HTTP/2 `:8082` — Booking бьёт в **8082**.
5. Жди готовности: БД + HTTP + gRPC; смотри health-тело и логи миграций.
6. Данные через API; ID из ответов; poll с deadline вместо Sleep; интервалы UTC в рабочих часах.
7. Цепочка: регистрация клиента → available yacht (Catalog) → create booking → read → проекция в Catalog. Оплата: checkout → тестовый webhook → re-read.
8. Докажи участие обоих сервисов (проекция Catalog ↔ бронь; логи gRPC). Два `/health` недостаточны.
9. `finally`: останови только ресурсы прогона; сравни git status с исходным.

## Полнота

Отдельный кейс: статус/тело; read-after-write; валидация входа; бизнес-правила; платежи/идемпотентность webhook; согласованность обеих БД; сбой Catalog/Gims через сеть стенда.

Успешный основной путь — через Booking **и** Catalog без подмены gRPC.
